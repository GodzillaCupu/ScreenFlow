# Prosedur Pengetesan (Testing Procedure) - ScriptFlow\n\nDokumen ini menjelaskan langkah-langkah dan prosedur untuk melakukan pengetesan aplikasi ScriptFlow, baik pada tahap pengembangan lokal (Local) maupun setelah aplikasi dinaikkan ke environment server (Staging/Production).\n\n---\n\n## 1. Pengetesan Secara Lokal (Local Testing)\n\nPengetesan di tahap lokal dilakukan oleh developer di perangkat masing-masing sebelum kode digabungkan (merge) atau di-deploy.\n\n### A. Menjalankan Aplikasi di Mode Debug\nLangkah pertama untuk memastikan fitur berjalan dengan baik adalah menjalankan aplikasi secara langsung di emulator atau perangkat nyata.\n- **Perintah:**\n  ```bash\n  flutter run\n  ```\n- **Tujuan:** Memvalidasi fungsionalitas UI secara langsung, navigasi antar halaman (seperti Login ke Dashboard), dan memastikan tidak ada error yang muncul di terminal.\n\n### B. Unit Testing\nMengetes fungsi atau metode secara individual untuk memastikan logika bisnis berjalan sesuai ekspektasi tanpa bergantung pada antarmuka pengguna (UI).\n- **Lokasi file:** Direktori `test/` (umumnya untuk file logika terpisah).\n- **Perintah:**\n  ```bash\n  flutter test\n  ```\n\n### C. Widget Testing\nMengetes satu bagian UI (widget) secara individu untuk memastikan elemen dirender dengan benar dan memberikan respons interaksi yang sesuai (misalnya, menekan tombol).\n- **Dalam Flutter:** Menggunakan `testWidgets`.\n- **Perintah:**\n  ```bash\n  flutter test test/widget_test.dart\n  ```\n\n### D. Integration Testing (Lokal)\nMengetes seluruh alur aplikasi dari awal hingga akhir di dalam emulator/perangkat nyata, untuk menguji interaksi antarkomponen.\n- **Lokasi file:** Direktori `integration_test/`\n- **Perintah:**\n  ```bash\n  flutter test integration_test\n  ```\n\n---\n\n## 2. Pengetesan di Server / Staging / Production (Server Testing)\n\nSetelah aplikasi di-build dan di-deploy ke environment server (Web Hosting, TestFlight, atau Google Play Console Internal), proses testing difokuskan pada simulasi penggunaan di dunia nyata.\n\n### A. Smoke Testing setelah Deployment\nPengetesan cepat yang dilakukan sesaat setelah rilis atau deployment sukses ke server untuk memastikan fitur utama tidak mengalami kegagalan fatal (*crash*).\n- **Langkah-langkah:**\n  1. Buka URL aplikasi web ScriptFlow yang sudah di-deploy, atau unduh aplikasi versi rilis.\n  2. Lakukan \"Login\" menggunakan akun *testing*.\n  3. Akses halaman \"Dashboard\".\n  4. Lakukan minimal satu aksi utama (misal: buka *script card* atau navigasi menu).\n\n### B. Pengujian Mode Rilis (Release Build Validation)\nAplikasi di server berjalan dalam mode \"Release\" yang telah dioptimasi, yang mungkin memperlihatkan perilaku sedikit berbeda dari mode lokal.\n- **Langkah-langkah:**\n  1. Pastikan tidak ada elemen UI yang *(overflow)* atau terpotong di berbagai rasio layar (Desktop, Tablet, Mobile).\n  2. Cek kecepatan transisi dan animasi; performanya harus lebih mulus.\n  3. Pastikan tidak lagi terdapat *pita* \"Debug\" di pojok kanan atas layar.\n\n### C. Uji Konektivitas API (Backend)\nAplikasi di server harus terhubung dengan benar ke API staging/production, tidak boleh lagi mengarah ke *localhost*.\n- **Langkah-langkah:**\n  1. Periksa pengambilan data dasar: pastikan data Dashboard/Script sesuai dengan *database* server.\n  2. Uji skenario jaringan: apa yang terjadi jika respons API melambat atau terdapat kendala jaringan sementara (validasi status *loading* dan respons *error*).\n\n### D. User Acceptance Testing (UAT)\nPengetesan fungsional dan *end-to-end* yang dilakukan dari kacamata pengguna sesungguhnya untuk memastikan sistem telah memenuhi persyaratan bisnis.\n- **Langkah-langkah:**\n  1. Jalani alur *User Story* yang sudah ditetapkan (dari awal buka aplikasi hingga *logout*).\n  2. Catat dan dokumentasikan jika ditemukan *bug* atau ketidaksesuaian desain/UX.\n\n---\n\n## Ringkasan Alur Testing:\n1. Kembangkan fitur di `lib/`.\n2. Lakukan `flutter test` (Unit/Widget Test) secara lokal.\n3. Uji coba dengan `flutter run` dalam mode *Debug*.\n4. Build aplikasi `flutter build ...` dan deploy ke lingkungan Server/Staging.\n5. Lakukan **Smoke Test** pada versi rilis di Server.\n6. Lakukan pengetesan API terhubung penuh & UAT sebelum dianggap *Selesai*.\n
